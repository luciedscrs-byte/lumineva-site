Automatisations · 5

Plan d’automatisations pour Lumineva

Un tableau par catégories et par mails, comme un tableau de suivi d’automatisations : quand le mail part, pour qui, ce qu’il dit, ce qui se passe ensuite, et comment le régler dans Shopify.

En clair

La question. Quelles automatisations mettre en place sur Shopify, et comment ?

Notre réponse. Huit catégories de mails (22 mails ou étapes), complétées par six Flow « invisibles » qui posent des tags et envoient des alertes à la gérante. On modifie les 4 automatisations actuelles et on en crée de nouvelles. Chaque ligne indique son outil Shopify et ses chiffres.

Les chiffres qui la soutiennent :

  1. Besoin : Lumineva n’a aujourd’hui que 7 automatisations (dont 4 actives, une avec son e-mail resté en brouillon) ; seules les relances panier et paiement ont rapporté des commandes (7 commandes, 842 €).
  2. Temps : la gérante dit manquer de temps ; ces automatisations tournent sans elle. Le temps gagné n’est mesuré dans aucun fichier : il est à demander (voir plus bas).
  3. Argent : faible et non prouvé (voir les autres pages). Ce n’est pas l’argument principal.

Niveau de preuve : Démontré pour les chiffres cités ; Hypothèse pour l’effet des mails et le temps gagné

3 · Pas à pas dans Shopify

Les chemins de menu sont décrits d’après l’aide de Shopify ; les noms exacts peuvent différer légèrement dans la boutique de Lumineva. Rien n’a été testé.

Créer un segment (exemple : les nouveaux clients à relancer à J+45)

  1. Dans l’administration Shopify : Clients, puis Segments, puis Créer un segment.
  2. Écrire les conditions (Shopify les propose dans une liste ; voir la référence des segments) : nombre de commandes = 1, dernière commande il y a 45 jours, abonné aux e-mails.
  3. Enregistrer le segment sous un nom clair, par exemple « R1 nouveau J+45 ».

Les noms exacts des conditions sont à vérifier dans l’éditeur de segments de la boutique.

Créer un Flow qui ajoute un tag (exemple : T2 « régulier »)

  1. Applications, puis Flow, puis Créer un workflow.
  2. Choisir le déclencheur « Commande créée ».
  3. Ajouter une condition : le nombre de commandes du client est supérieur ou égal à 3.
  4. Ajouter l’action « Ajouter des tags au client » avec le tag « regulier ».
  5. Nommer le workflow (« T2 tag régulier »), puis l’activer.

Créer un Flow d’alerte (exemple : T4 commande non expédiée après 7 jours)

  1. Applications, Flow, Créer un workflow, déclencheur « Commande créée ».
  2. Ajouter l’action « Attendre » : 7 jours (le maximum est de 90 jours).
  3. Ajouter une condition : l’état d’expédition de la commande n’est pas « expédié ».
  4. Si oui : action « Envoyer un e-mail interne » (à la gérante) et « Ajouter un tag à la commande » : « retard-7j ». Activer.

L’action « envoyer un e-mail interne » n’a pas pu être confirmée dans l’aide de Shopify : à vérifier dans l’éditeur.

Rappeler un code seulement à ceux qui ne l’ont pas utilisé (campagne G)

  1. Créer le code dans Réductions (par exemple PRINTEMPS10).
  2. Créer le Flow T3 : « Commande créée », condition « le code de réduction est PRINTEMPS10 », action « tag client » : « code-PRINTEMPS10 ».
  3. Dans Clients, Segments : abonné aux e-mails et sans le tag « code-PRINTEMPS10 ».
  4. Dans Marketing, Automatisations (ou une campagne) : envoyer le rappel à ce segment.

Limites et ce qui manque

  • Aucun effet de ces mails n’est démontré : les chiffres cités sont la situation de départ, pas un résultat promis.
  • Les délais (J+3, +24 h…) sont des propositions, sauf pour la relance par profil, déduite des courbes de retour.
  • Les noms de menus et d’actions Shopify viennent de la documentation et de forums : à vérifier dans la boutique avant de présenter.
  • Lumineva envoie le mail « marketing » seulement aux abonnés (81 % des clients) ; les autres n’ont droit qu’aux mails de commande.
