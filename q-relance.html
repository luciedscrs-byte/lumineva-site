Faut-il une relance après la 1re commande, et quand l’envoyer ?

Quand l’envoyer, combien de clients viser, ce qu’elle pourrait rapporter, et comment le vérifier.

Combien reviennent, et quand ?

  • FaitSur les 829 clients suivis, 8,2 % ont recommandé à J+30, 11 % à J+45, 15 % à J+60, 20 % à J+90 et 29 % à J+180. Environ 7 clients sur 10 ne reviennent jamais.
  • FaitParmi ceux qui reviennent, le délai médian est de 64,5 jours. Le retour est étalé : aucun moment ne concentre les retours.
  • Fait84 % des fiches clients acceptent les e-mails (82 % des clients suivis) : la relance peut toucher la plupart d’entre eux.

Quand l’envoyer ?

  • FaitSans relance, environ 8 % des clients qui n’ont pas encore recommandé à J+45 commandent dans les 30 jours suivants ; 6 % à partir de J+60. Le retour « naturel » reste faible à tout moment.
  • Interprétation possibleJ+45 est un bon compromis : avant le délai médian de retour (64 jours), quand le retour naturel est encore possible mais loin d’être acquis, et avec 481 clients joignables par an. Ce choix est raisonné, pas démontré : seule une comparaison entre deux moments d’envoi le montrerait.
  • LimiteAu rythme actuel, 25 clients se trouvent aujourd’hui entre 45 et 90 jours de leur première commande sans avoir recommandé (23 joignables) : les arrivées de nouveaux clients ont ralenti en été 2026.

Ce qu’elle pourrait rapporter

  • FaitChaque année, environ 481 clients à une seule commande sont joignables à J+45. Si la relance fait revenir 5 points de plus, cela fait environ 24 commandes de plus par an, soit 1 652 € de chiffre d’affaires et 590 € à 826 € de marge.
  • FaitAvec un code de 10 %, le gain fond : la remise est aussi donnée aux clients qui seraient revenus de toute façon. À +2 points la marge devient négative ; à +5 points elle tombe à 148 € à 384 €.
  • Interprétation possibleUne relance sans remise, qui propose un produit voisin de ce qu’a acheté le client, est plus rentable qu’une relance avec code.
  • LimiteLes scénarios supposent l’effet : il n’est pas mesuré. Les gains restent modestes (moins de 1 000 € de marge par an), car le flux de nouveaux clients est limité.

Ce que pourrait rapporter la relance à J+45 (scénarios)

On ne connaît pas l’effet réel : on suppose que la relance fait revenir 2, 5 ou 10 points de clients de plus. Commande moyenne : 68,70 €.   • FaitLe panier monte de 4,38 € entre la 1re et la 2e commande (par le prix des articles). Seuls 24 % rachètent le même produit ; 80 % rachètent au moins une famille déjà prise ; 62 % découvrent une nouvelle famille.

Ce qui change et ce qui ne change pas d'une commande à l'autre

Ce qui ne change pas
  • Le nombre d'articles (≈ 3,5 par commande).
  • La famille de produits : 198 clients sur 248 (80 %) rachètent au moins une famille déjà achetée à la 1re commande.
  • Le poids des bougies gourmandes (71 % des 1res commandes, 65 % des 2es).
  • Le retrait local (≈ 18 à 19 % des commandes).
Ce qui change
  • Le produit exact : seulement 59 clients sur 248 (24 %) rachètent le même produit ; 9 % des produits de la 2e commande ont déjà été achetés.
  • La famille dominante : identique pour 112 clients sur 248 (45 %).
  • 154 clients sur 248 (62 %) découvrent une nouvelle famille à la 2e commande.
  • Le code promo : 53,6 % → 13,3 %.
  • Le montant de la 2e commande : plus élevé pour 117 clients, moins pour 90, à ±5 € pour 41.

Interprétation possible : le client fidèle reste sur l'univers « bougie » mais change de parfum, ce qui est cohérent avec un catalogue de parfums de saison. Limite : le catalogue change avec les lancements, donc « ne rachète pas le même produit » peut simplement vouloir dire que le produit n'existe plus.

Ce qu'il faut retenir avant de lire l'arbre : l'arbre est testé sur des clients qu'il n'a pas vus (validation croisée en 5 parties). Résultat : AUC = 0,51 ± 0,03, alors que 0,50 = hasard pur. Conclusion honnête : ni le contenu de la 1re commande, ni le lieu, ni le niveau de vie ne permettent de prévoir qui reviendra. Les branches ci-dessus décrivent l'échantillon mais ne se généralisent pas ; elles sont montrées pour la démonstration de la méthode et ne doivent pas servir à cibler des clients.

Les analyses qui manquent

  • L’effet réel d’une relance : inconnu. Pour le mesurer par un test (une moitié des clients reçoit la relance, l’autre non), il faudrait environ 604 clients par groupe pour détecter un gain de 5 points, soit plus de deux ans de flux au rythme actuel. Même pour 10 points, il en faudrait environ 178 par groupe.
  • Plus réaliste : envoyer la relance à tous les clients et comparer le retour à J+90 avec celui de la même période de l’année précédente (mais la comparaison est fragile).
  • Le coût d’envoi d’un e-mail (inconnu) et la liste des produits voisins à proposer, famille par famille.

Premier constat, avec ce qu’on a déjà

  • Recommandation : relancer à J+45, sans remise, avec un produit voisin de celui déjà acheté.
  • Ordre de grandeur : 590 € à 826 € de marge par an si la relance fait revenir 5 points de plus.
  • Elle se vérifie en suivant le retour à J+90 des clients relancés, pas avec un test (trop peu de clients).

def km(dur, ev, tmax=400):
    ts = sorted(set(dur[ev == 1])); S = 1.0; pts = [(0, 1.0)]; var_acc = 0.0; ci = []
    for t in ts:
        if t > tmax: break
        n_risk = (dur >= t).sum(); d = ((dur == t) & (ev == 1)).sum()
        S *= (1 - d / n_risk); var_acc += d / (n_risk * (n_risk - d)) if n_risk > d else 0
        pts.append((float(t), float(S))); ci.append((float(t), float(S), float(S * np.sqrt(var_acc))))
    return pts, ci
pts, ci = km(dur, ev)
def S_at(t):
    s = 1.0
    for tt, ss in pts:
        if tt <= t: s = ss
        else: break
    return s
def se_at(t):
    e = 0.0
    for tt, ss, se in ci:
        if tt <= t: e = se
        else: break
    return e

def build_events(customers):
    """Retourne [(duree_jours, evenement)] : evenement=1 si 2e commande observée, 0 si censuré."""
    ev = []
    for os_ in customers:
        first = os_[0]['dt']
        if len(os_) >= 2:
            ev.append(((os_[1]['dt']-first).days, 1))
        else:
            ev.append(((REF-first).days, 0))
    return ev

def kaplan_meier(events, tmax=270):
    """Estimateur de Kaplan-Meier : renvoie liste de (t, %ayant_recommandé) en escalier."""
    times = sorted(set(t for t,e in events if e==1 and t<=tmax))
    n_at_risk = len(events)
    s = 1.0
    curve = [(0,0.0)]
    remaining = sorted(events, key=lambda x:x[0])
    idx = 0
    at_risk = len(events)
    for t in times:
        d = sum(1 for tt,e in events if tt==t and e==1)
        # nombre encore à risque juste avant t : tous ceux dont la durée >= t
        at_risk_t = sum(1 for tt,e in events if tt >= t)
        if at_risk_t > 0:
            s *= (1 - d/at_risk_t)
        curve.append((t, round((1-s)*100,2)))
    curve.append((tmax, curve[-1][1]))
    return curve

def logrank(evA, evB):
    """Test du log-rank (comparaison de 2 courbes de survie), khi² à 1 ddl."""
    all_times = sorted(set(t for t,e in evA+evB if e==1))
    O_A=E_A=V=0.0
    for t in all_times:
        nA = sum(1 for tt,e in evA if tt>=t); nB = sum(1 for tt,e in evB if tt>=t)
        dA = sum(1 for tt,e in evA if tt==t and e==1); dB = sum(1 for tt,e in evB if tt==t and e==1)
        n, d = nA+nB, dA+dB
        if n <= 1 or d == 0: continue
        O_A += dA
        E_A += d*nA/n
        V += d*(nA/n)*(nB/n)*((n-d)/(n-1))
    chi2 = (O_A-E_A)**2/V if V>0 else 0
    p = stats.chi2.sf(chi2, df=1)
    return chi2, p

evA = build_events([os_ for os_ in cust.values() if os_[0]['code']=='BIENVENUE10'])
evB = build_events([os_ for os_ in cust.values() if not os_[0]['code']])
evAll = build_events(list(cust.values()))

curveA = kaplan_meier(evA)
curveB = kaplan_meier(evB)
